# Issue 01: End-to-End Implementation of P0 and P1 Valuation Integrity Remediations

Status: resolved (pending coordinator verification)
Type: task

## Description

Implement all seven P0 and P1 valuation integrity fixes authorized in `.scratch/valuation-integrity/spec.md`:
1. [P0-A] Multi-class point-in-time share capital reconciliation.
2. [P0-B] True 4-quarter non-overlapping TTM statement rollup with annual fallback.
3. [P0-C] Calendar-anchored DCF forecasting, ACT/365 discounting, and display hygiene.
4. [P1-D] NTM consensus horizon selection with verified fiscal year day-weighting.
5. [P1-E] Configurable derived growth rate floor and cap without request leakage.
6. [P1-F] Dynamic model weight overrides with cash flow group cap (default 40%) and edge-case handling.
7. [P1-G] 3x3 terminal value sensitivity matrix with TV/EV ratio threshold alerts.

Update backend engines, models, providers, services, and API; update frontend types, API, UI components (collapsible advanced controls, DCF sensitivity grid, TTM/share badges), and Markdown export. Verify with unit, integration, API, and browser end-to-end tests.

## Implementation Details

1. **[P0-A] Share Capital Reconciliation**:
   - Implemented cross-checks between `impliedSharesOutstanding`, `sharesOutstanding`, quarterly/annual BS ordinary shares, and `marketCap / currentPrice`.
   - Populated `shares_basis` ("ALL_CLASS_RECONCILED", "SINGLE_CLASS_VERIFIED", "BALANCE_SHEET_ORDINARY", "CONFLICT_DEGRADED") and structured `shares_reconciliation` dictionary.
   - Preserved evidence-based truth: never fabricated shares from marketCap/price; severe conflicts degrade explicitly with notes.

2. **[P0-B] True TTM Statement Rollup & Annual Fallback**:
   - Implemented 4-quarter discrete summing for flow items via `backend/app/providers/statement_aggregator.py`.
   - Continuous interval verification (60–125 days) and cumulative YTD detection & de-accumulation.
   - Strict 4/4 completeness per metric, with graceful `statement_basis="ANNUAL_FALLBACK"` and `annual_fallback=True`.
   - Point-in-time latest quarterly balance sheet extraction without summing balance sheets.
   - Matched interest/tax for FCFF (unlevered free cash flow).

3. **[P0-C] Calendar-Anchored DCF**:
   - Calendar-anchored projection dates with true ACT/365 day fractions: $t_k = (E_k - \text{as\_of}).\text{days} / 365.0$.
   - Exponential continuous discounting $\exp(t \cdot \ln(1 + \text{WACC}))$ handling leap years (e.g. 2028: $t_2 = 731 / 365 = 2.0027$).
   - Shared pure calculator `_calculate_dcf` for base scenario and all 3x3 sensitivity cells without center-cell copying hacks.

4. **[P1-D] Consensus Horizon Selector (NTM / FY1 / FY2)**:
   - Configured default forecast horizon to `"ntm"` (`DEFAULT_FORECAST_HORIZON = "ntm"`).
   - Exact bounded day weights $w_0 \in [0, 1], w_1 = 1 - w_0$ using exact fiscal year duration.
   - Blended both EPS and Revenue; graceful fallback to `current_fy` with warning if FY2 is missing.

5. **[P1-E] Configurable Derived Growth Bounds**:
   - Request-scoped projection module `backend/app/services/projections.py`.
   - `growth_floor` (default `-0.20`, validated `> -1.0`) and `growth_cap` (default `0.40`, validated `<= 2.0`) dynamically clamp derived EBITDA, FCF, FCFF, and DCF without mutating snapshot or provider cache.

6. **[P1-F] Dynamic Model Weights & Cash Flow Group Cap**:
   - Sparse override merging: missing fields merge with default weights before validating at least one positive.
   - Validation ensures all-zero weights raise 422, single-sided growth bounds check `floor <= cap`.
   - 40% cashflow group weight cap enforced when multiple-based models are present.
   - When only cash flow models are available, composite fair value is withheld under policy and surfaced with `cashflow_group_policy_message` and `cashflow_sensitivity`.

7. **[P1-G] 3x3 Terminal Value Sensitivity Matrix & UI Integration**:
   - Generated 3x3 grid around base WACC (±1.0%) and perpetual growth $g$ (±0.5%).
   - Monotonicity verified; TV/EV ratio dependence alerts surfaced for TV/EV > 70% and > 80%.
   - Frontend renders `DCFSensitivityMatrixTable`, collapsible Advanced Controls, badges, and `cashflow_group_policy_message`.
   - Markdown export captures complete 3x3 sensitivity matrix, active weights, and shares reconciliation.
