# 三、致命问题

## 致命问题 1：所谓“Forward EBITDA / FCFE / FCFF”仍然不是真正的前瞻预测

这是当前版本最严重的问题。

系统现在看起来有了 `forward_ebitda`、`forward_fcfe`、`forward_fcff_1y`、`forward_fcff_2y`，但仔细看生成过程，它们其实仍然是：

> **旧年报数字 × 一个统一增长率**

甚至 EBITDA、FCFE、FCFF 经常使用完全相同的增长率。

### AMD

报告：

`FY2025 EBITDA $7.275B × 1.40 = Forward EBITDA $10.185B`

而这个40%不是分析师 EBITDA consensus，而是增长率达到上限后被 `clamp` 到40%。

FCFE又是：

`$8.226B × 1.40 = $11.516B`。

DCF：

`FY2025 FCFF $6.84B → FY1E $9.57B`

也是 `×1.40`。

也就是说，系统实际假设：

> EBITDA增40%
> FCFE增40%
> FCFF增40%

这没有财务逻辑上的必然关系。

而 AMD 2026 Q2 已经公布：

收入同比 **+50%**，Adjusted EBITDA 单季 $3.315B、上半年已经达到 $6.061B；现金及短期投资已经是 $13.111B，而不是报告继续使用的 $10.552B。([Advanced Micro Devices, Inc.][1])

上半年 EBITDA 都已经有 $6.06B，系统却还从旧的 $7.275B 年度 EBITDA 人工乘40%得到全年/forward $10.185B。

**这不是预测，而是算法造出了一个预测值。**

### NVDA更加明显

系统：

`FY base EBITDA $144.552B × 1.40 = $202.373B`

然后：

`FCFE $96.676B ×1.40 = $135.346B`

以及：

`FCFF $96.896B → $135.65B → $189.92B`

全部围绕40%增长率展开。  

但 NVIDIA 已经在2026年8月26日公布最新财报：

Q2 FY2027 收入 **$96.2B，同比+106%**，Data Center **$89B，同比+117%**。([NVIDIA Newsroom][2])

因此用一个人工40% cap 去产生 EBITDA、FCF，本质上已经脱离公司当前经营轨迹。

### 应当怎样修

这应该成为一个**硬规则**：

> 只要可以获得分析师 EBITDA / EPS / revenue / operating income / CapEx consensus，就禁止 `historical metric × revenue_growth` 生成“forward metric”。

如果只能获取 Revenue 和 EPS，那么 EBITDA 应该通过：

`Revenue forecast × EBITDA margin forecast`

FCFF则应该：

`EBIT × (1-T) + D&A - CapEx - ΔNWC`

而不能：

`去年FCFF × revenue growth`

在当前这个问题修复前，我会直接把 **EV/EBITDA、FCF Yield、DCF三个模型标记为低可信度**。

但 Alphabet 2026 Q2：

现金+marketable securities 已从 **$126.843B → $242.474B**。([證券交易委員會][3])

## 严重问题 4：GOOG 的 NTM EPS仍然包含巨额一次性/非经营收益

FY2 EPS = $14.85

然后：

`30.7%×20.60 + 69.3%×14.85 = $16.61`

再：

`16.61×20 = $332.20`。

数学正确。

Alphabet 2026 Q2 的 Other Income 是约 **$98B**，其中主要来自权益证券的 **$99B net gains**，绝大部分为未实现收益。([證券交易委員會][5])

`normalized EPS`

把非经营性未实现投资收益剔除，再做资本化。

否则 P/E 模型本身存在污染。

不是数学错误，但假设非常激进。

# 八、我建议下一版设置“禁止出估值”的硬门槛

比继续调参数更重要的是建立 **valuation validity gate**。

建议直接在后端加入以下规则：

| 条件                                           | 系统行为                                |
| -------------------------------------------- | ----------------------------------- |
| 已有最新10-Q，但只能取得旧年报                            | **禁止 DCF / FCF / EV EBITDA进入综合值**   |
| Forward EBITDA/FCF 只能通过 historical×growth 推导 | 标记 `synthetic_forward`，权重最多10%，最好禁用 |
| 全部 multiples 都来自 fallback                    | **不得输出“低估/高估”评级**                   |
| 最大模型FV / 最小模型FV >1.5x                        | 输出 `MODEL_DISAGREEMENT`，不生成单一综合目标价  |
| TV/EV >75%                                   | DCF权重减半                             |
| TV/EV >80%                                   | DCF仅作为敏感度展示                         |
| 使用 common shares 而没有 diluted shares          | 降级数据质量                              |
| FY EPS含重大一次性项目                               | 强制 normalized EPS                   |
| NTM可获得季度预测                                   | 使用未来四季度相加，禁止年度线性插值                  |
| FCF/EBITDA增长率完全等于Revenue growth              | 标记 `synthetic_metric_warning`       |

如果应用其中最关键的一条——

**模型估值差异超过50%时禁止机械平均**——

这四份报告里至少 AMD 和 NVDA 会直接触发报警，GOOG也接近；META则会明确识别 $1,154 EV/EBITDA 为异常模型。
